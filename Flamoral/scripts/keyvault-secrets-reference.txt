=============================================================================
Flamoral Production Key Vault Secrets - Quick Reference
=============================================================================

VAULT NAMES:
-----------
1. flamoralprodauthkv      - Authentication (JWT, OAuth, sessions)
2. flamoralprodpaymentkv   - Payment providers (Stripe, IAP)
3. flamoralproddatakv      - Database and cache (Postgres, Redis)
4. flamoralprodexternalkv  - Third-party APIs (SendGrid, Twilio, etc.)
5. flamoralprodinfrakv     - Infrastructure (service keys, encryption)

=============================================================================
POPULATE ALL SECRETS (Initial Setup)
=============================================================================

Windows (PowerShell):
    cd DatingPlatform\scripts
    .\populate-prod-keyvault-secrets.ps1

Linux/Mac (Bash):
    cd DatingPlatform/scripts
    chmod +x populate-prod-keyvault-secrets.sh
    ./populate-prod-keyvault-secrets.sh

=============================================================================
LIST SECRETS IN EACH VAULT
=============================================================================

az keyvault secret list --vault-name flamoralprodauthkv --output table
az keyvault secret list --vault-name flamoralprodpaymentkv --output table
az keyvault secret list --vault-name flamoralproddatakv --output table
az keyvault secret list --vault-name flamoralprodexternalkv --output table
az keyvault secret list --vault-name flamoralprodinfrakv --output table

=============================================================================
VIEW A SECRET VALUE
=============================================================================

az keyvault secret show \
  --vault-name VAULT_NAME \
  --name SECRET_NAME \
  --query value \
  --output tsv

Example:
    az keyvault secret show \
      --vault-name flamoralprodauthkv \
      --name jwt-secret \
      --query value \
      --output tsv

=============================================================================
UPDATE/SET A SECRET
=============================================================================

az keyvault secret set \
  --vault-name VAULT_NAME \
  --name SECRET_NAME \
  --value "SECRET_VALUE"

Examples:

  # Update Stripe secret key
  az keyvault secret set \
    --vault-name flamoralprodpaymentkv \
    --name stripe-secret-key \
    --value "sk_live_YOUR_KEY"

  # Update SendGrid API key
  az keyvault secret set \
    --vault-name flamoralprodexternalkv \
    --name sendgrid-api-key \
    --value "SG.YOUR_KEY"

  # Set secret from file (for JSON keys, certificates, etc.)
  az keyvault secret set \
    --vault-name flamoralprodexternalkv \
    --name firebase-private-key \
    --file firebase-service-account.json

=============================================================================
DELETE A SECRET (Use with caution!)
=============================================================================

az keyvault secret delete \
  --vault-name VAULT_NAME \
  --name SECRET_NAME

# Purge deleted secret (PERMANENT - cannot recover!)
az keyvault secret purge \
  --vault-name VAULT_NAME \
  --name SECRET_NAME

# Recover soft-deleted secret (within retention period)
az keyvault secret recover \
  --vault-name VAULT_NAME \
  --name SECRET_NAME

=============================================================================
GRANT ACCESS TO VAULTS
=============================================================================

# Grant user access (for management)
az role assignment create \
  --role "Key Vault Secrets Officer" \
  --assignee USER_PRINCIPAL_ID \
  --scope /subscriptions/SUB_ID/resourceGroups/flamoral-prod-rg/providers/Microsoft.KeyVault/vaults/VAULT_NAME

# Grant AKS managed identity access (for app access)
az role assignment create \
  --role "Key Vault Secrets User" \
  --assignee AKS_IDENTITY_OBJECT_ID \
  --scope /subscriptions/SUB_ID/resourceGroups/flamoral-prod-rg/providers/Microsoft.KeyVault/vaults/VAULT_NAME

# Get AKS kubelet identity
az aks show \
  --resource-group flamoral-prod-rg \
  --name flamoral-prod-aks \
  --query "identityProfile.kubeletidentity.objectId" \
  --output tsv

=============================================================================
NETWORK ACCESS
=============================================================================

# Add your IP to vault firewall (temporary access)
az keyvault network-rule add \
  --name VAULT_NAME \
  --ip-address YOUR_IP_ADDRESS

# Remove IP from firewall
az keyvault network-rule remove \
  --name VAULT_NAME \
  --ip-address YOUR_IP_ADDRESS

# List current network rules
az keyvault network-rule list \
  --name VAULT_NAME \
  --resource-group flamoral-prod-rg

# View audit logs (requires Log Analytics)
az monitor activity-log list \
  --resource-group flamoral-prod-rg \

  --output table

# Query Key Vault logs in Log Analytics
az monitor log-analytics query \
  --workspace WORKSPACE_ID \
  --analytics-query "AzureDiagnostics | where ResourceType == 'VAULTS' | take 100" \
  --output table

=============================================================================
GENERATE NEW RANDOM SECRETS
=============================================================================

# Generate 64-character random string (JWT secrets)
openssl rand -base64 48

# Generate 32-character random string (session secrets)
openssl rand -base64 24

# Generate 32-byte hex string (encryption keys)
openssl rand -hex 32

# PowerShell equivalent
[Convert]::ToBase64String((1..48 | %{Get-Random -Minimum 0 -Maximum 256}))

=============================================================================
ROTATE SECRETS
=============================================================================

Use the automated rotation script:
    cd DatingPlatform/scripts/deployment
    ./rotate-secrets.sh

Or manually:
    1. Generate new secret value
    2. Update Key Vault with new value
    3. Restart affected services/pods
    4. Verify new secret is working
    5. (Optional) Keep old version as backup

Example:
    NEW_JWT_SECRET=$(openssl rand -base64 48)
    az keyvault secret set \
      --vault-name flamoralprodauthkv \
      --name jwt-secret \
      --value "$NEW_JWT_SECRET"
    kubectl rollout restart deployment/auth-service

=============================================================================
BACKUP AND DISASTER RECOVERY
=============================================================================

# Backup all secrets from a vault
for secret in $(az keyvault secret list --vault-name VAULT_NAME --query "[].name" -o tsv); do
    az keyvault secret backup \
      --vault-name VAULT_NAME \
      --name $secret \
      --file "${secret}.backup"
done

# Restore a secret
az keyvault secret restore \
  --vault-name VAULT_NAME \
  --file secret-name.backup

=============================================================================
TROUBLESHOOTING
=============================================================================

Problem: "Forbidden" or "Access Denied" errors
Solution:
    1. Check you have correct role assignment:
       az role assignment list --assignee $(az ad signed-in-user show --query id -o tsv)
    2. Wait 5-10 minutes for permissions to propagate
    3. Ensure you're using RBAC (not access policies)

Problem: Network access denied
Solution:
    1. Add your IP to firewall (see NETWORK ACCESS above)
    2. Or use Azure Cloud Shell (bypass firewall)

Problem: Pods can't access secrets
Solution:
    1. Verify CSI driver: kubectl get pods -n kube-system | grep secrets-store
    2. Check SecretProviderClass: kubectl get secretproviderclass -A
    3. Verify AKS identity has access (see GRANT ACCESS above)
    4. Check pod logs: kubectl logs POD_NAME
